# 1. Registrar decisões arquiteturais relevantes

######  Date: 2026-09-24 4:11pm

## Contexto (Teste técnico avaliável)

Uma vez que este projeto reflete a natureza de um teste técnico a ser avaliado, é relevante \
considerar que o avaliador também irá averiguar a tomada de decisão isso leva a crer ser de critério \
avaliativo o registro das decisões técnicas tomadas durante o desenvolvimento desta atividade

## Decisão (Utilização de um ADR "Registro de decisões arquiteturais")

Utilizar um modelo de documentação já conhecido e adotado no desenvolvimento de software, conhecido \
como ADR a architecture-decision-log, descrito em [architecture-decision-record](https://github.com/architecture-decision-record/architecture-decision-record) \
exemplo de uso em [modular-monolith-with-ddd](https://github.com/kgrzybek/modular-monolith-with-ddd/tree/master/docs)

## Motivação (Esclarecimento de estratégias)

Trará o ponto de vista do developer em relação aos pontos adotados por este projeto juntamente com \
suas motivações e consequências melhor esclarecendo a estratégia por trás da utilização de cada \
conceito arquitetural
